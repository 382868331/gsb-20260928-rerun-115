# 虚拟总线运行系统

这是一个纯 Go、无硬件依赖的教学版虚拟总线系统。首轮协议选用有限的 7 位地址、仅写入、I2C 风格两线协议，后续协议可以继续沿用电平事件与设备边界扩展。

## 组成

- `bus/clock.go`：确定性虚拟时钟，回调只按虚拟时间触发。
- `bus/bus.go`：SDA/SCL 开漏线、线与电平、仲裁可见性、电平归属记录和总线复位。
- `bus/master.go`：主设备状态机，负责 START、数据位、仲裁检测、ACK/NACK、重复 START 和 STOP。
- `bus/slave.go`：从设备边沿解码器，只订阅解析后的 SDA/SCL 事件，不读取主设备内部状态。
- `bus/bus_test.go`：竞争、从设备无响应、重复启动、中途复位和电平归属测试。

## 协议规则

- 两线均为开漏：设备只能主动拉低，释放后由上拉电阻恢复高电平。
- START：SCL 为高时 SDA 从高变低；STOP：SCL 为高时 SDA 从低变高。
- 数据位只能在 SCL 低电平期间改变，在 SCL 高电平期间采样。
- 主设备发送高电平位时若读到解析后的 SDA 为低，立即丢失仲裁并释放总线。
- 第 9 个时钟槽由从设备驱动：低电平为 ACK，高电平表示无响应或 NACK，等待会正常结束。
- 一个事务内连续多个 `Message` 使用重复 START，不先产生 STOP。
- `Bus.Reset()` 丢弃未来回调、递增世代号并释放所有线路驱动，避免复位后永久占用。

## 电平记录

`Bus.Segments()` 返回时间有序的稳定电平片段。每个片段列出造成该电平的来源：

- HIGH：归属于 `PULLUP`。
- LOW：归属于所有正在拉低的设备，例如主设备和从设备在 ACK 切换瞬间可能同时出现。
- 多个设备在同电平交接时也会拆分片段，因此能解释 ACK 从主设备切换到从设备的过程。
